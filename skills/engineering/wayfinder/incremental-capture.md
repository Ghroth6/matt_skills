# Incremental capture

Keep important changes in understanding recoverable while charting. Capture
meaning needed to continue, not a transcript of every exchange.

1. **Locate the delta.** Compare the new information with the effort's saved
   sources. Identify changes to the goal, constraints, user corrections and
   their reasons, rejected interpretations, or unresolved questions. Keep
   confirmed decisions, tentative ideas, and agent suggestions distinct.
   This step is complete when each material change is either already captured
   or identified for saving. With no uncaptured change, continue discussion
   without a persistence write.

2. **Save at its home.** Update an existing authoritative artifact when the
   information belongs there. For necessary information without such a home,
   reuse the user-named effort issue's `Working context` section. If no effort
   issue exists, create an ordinary issue on the configured tracker only when
   there is an uncaptured change, within the task's write authorization. Read
   the current issue before editing; preserve unrelated content and updates.
   Include enough context to understand a correction, its current meaning,
   and why it matters. The step is complete when every identified change has
   a saved home or a specific, visible write failure. A failed write leaves
   the information unsaved; report that gap and the next action needed.

3. **Verify and expose the entry.** Read back the changed artifacts and check
   the meaning, status, and relevant references. Give the user the effort
   issue's reference as the continuation entry. The step is complete only
   when that entry reaches the saved information; an unsaved gap remains
   explicit in the response rather than being described as a checkpoint.

**Resume** by reading the effort issue and the sources needed for the current
question. Start from its unresolved frontier; tentative ideas stay tentative.

**Absorb** a buffered entry when it gains a proper home, such as a decision
ticket, scope boundary, or domain document. Preserve its meaning and rationale
there, verify the destination, then replace the buffered detail with a source
reference. When all entries are absorbed, the effort issue retains only the
continuation references and its normal task content. Issue closure follows
the repository's workflow. The map keeps an index rather than absorbing the
discussion history.
